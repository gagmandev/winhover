# winhover（阿墨 · 窗口透明度）

一个常驻托盘的 Windows 小工具：**鼠标往任意窗口的标题栏右上角一停，就冒出一个控制面板**。
透明度、置顶、鼠标穿透、移出即隐藏、挂机保活，都在这个小面板里。

类似 WindowTop，但更轻——而且多了两个它没有的：**鼠标移出就自动隐藏**、**防挂机踢下线的保活**。

---

## 快速开始

1. 双击 `dist\AmoWinTrans.exe`（单文件，约 250 KB，需要 **.NET 8 桌面运行时**）。
   不想装运行时：跑一次 `publish-portable.bat`，会生成零依赖的 `dist-standalone\AmoWinTrans.exe`（约 66 MB）。
2. 右下角托盘出现一个圆形图标，弹一次气泡提示。
3. 把鼠标移到**任意窗口标题栏**上（按钮会出现在标题栏右侧、最小化按钮的左边），
   停在小胶囊上 → 展开面板 → 拖滑块。

> 第一次运行会出现在托盘里；如果没看到，点托盘区的 `▲` 展开。

## 悬停按钮不显示怎么办

先看这三处，状态都是明摆着的：

| 看哪 | 能看到什么 |
| --- | --- |
| **托盘图标** | 蓝色 = 已启用，**灰色 = 已停用** |
| **鼠标停在托盘图标上** | 提示里直接写着「悬停按钮：已启用 / 已停用」 |
| **右键托盘图标** | 菜单项写着「悬停按钮：已启用（点一下停用）」 |

还是不出来？右键托盘图标 → **「为什么悬停按钮没出来？」**，
它会把当前状态和最近一次的判定原因摊开给你看，比如：

```
悬停按钮：已启用
触发区域：只在标题栏
鼠标位置：3403, 528
鼠标下面的窗口：Qt51514QWindowIcon
最近一次判定：鼠标不在触发区域（当前是「只在标题栏」，鼠标在 3403,528，
              窗口 2747,89 起 1029x861，标题栏高 36）
```

常见的几种"不显示"：

| 判定原因 | 怎么办 |
| --- | --- |
| 悬停按钮已停用 | 双击托盘图标，或菜单里点一下 |
| 鼠标不在触发区域 | 把鼠标移到窗口**标题栏**上（或者托盘菜单 → 触发区域 → 整个窗口） |
| 窗口太小 / 铺满整屏 / 没有标题栏 | 这个窗口本身不支持，换个窗口 |
| 窗口已最小化 | 还原窗口 |
| 鼠标在桌面或任务栏上 | 移到窗口上 |

> 以前这里有两个开关（菜单里一个"启用悬停按钮"、双击托盘一个"暂停"），
> **两个都必须是"开"才会显示，而且都不显示状态** —— 点来点去都点不对。
> 现在合并成一个了。

## 面板说明

| 元素 | 作用 |
| --- | --- |
| 滑块 | 调透明度，范围 10% ~ 100%（面板上滚轮也能调） |
| 100/80/60/40/20% | 快捷预设 |
| 置顶 | 窗口置顶（再点取消） |
| 穿透 | 鼠标穿透，点得穿窗口；再按一次或 Ctrl+Alt+Z 取消 |
| 连按 | 自动连按某个键。**左键**开/关，**右键**改设置 |
| 隐藏 | 鼠标移出这个窗口就把它变成全透明（看不见），移回来恢复 |
| 保活 | 每分钟给窗口补一点输入，防挂机被踢下线（云原神等） |
| 重置 | 透明度、置顶、穿透、连按全部恢复原样 |

## 保活（防挂机踢下线）

点面板上的**「保活」**开启。适合云原神这类**长时间不操作就自动退出**的服务。

开启后每分钟给这个窗口补一次**按键**，让窗口背后的服务认为你还在操作。

### 发的是什么（默认：W / S 各点一下）

| 选项 | 效果 | 说明 |
| --- | --- | --- |
| **W / S 各点一下**（默认） | 角色走一小步再退回来 | 净位移约 0，不换目标、不推进剧情 |
| 空格轻点 | — | ⚠️ **剧情对话里空格是"推进对话"**，会把不想跳过的剧情跳掉 |
| Ctrl 轻点 | 无 | 单独按没有游戏效果，但有些客户端会过滤纯修饰键 |
| 鼠标微动 1 像素 | 无 | ⚠️ 见下面「为什么不用鼠标」——很可能压根不算输入 |

切换：**托盘菜单 →「保活发送什么」**。

> **为什么默认不用鼠标？** 实测 `PostMessage` 注入的 `mousemove`，页面里拿到的
> **`movementX` / `movementY` 是 0**（浏览器是从真实输入设备的位移算的，
> 合成的窗口消息没有这个信息）。而第三人称游戏基本都用「指针锁定 + 相对位移」
> 控制视角，客户端发出去的就是 movementX/Y —— 全是 0，等于没输入，保活白做。
> 按键没有"位移"这个概念，`keydown` 就是 `keydown`，客户端一定会转发。

### 想让它看不见，又不想断线？用「挪走」

**右键点面板上的「保活」** → 窗口被挪到屏幕外（看不见了，但保活照常）。

**挪回来有三种办法**（窗口看不见时鼠标够不到它，所以快捷键是主要入口）：

1. **按 `Ctrl+Alt+B`** ← 最方便，出厂就配好了
2. 托盘菜单 →「把所有挪走的窗口挪回来（Ctrl+Alt+B）」
3. 退出程序（退出时会自动把所有窗口恢复原样）

> ⚠️ **别用「最小化」**。实测窗口最小化之后，浏览器会**直接丢弃**注入的输入 ——
> `PostMessage`、`SendMessage`、发给子窗口，三种方式全部无效（还原后立刻恢复正常）。
> 所以想"看不见但还活着"，得用「挪走」而不是最小化。
>
> 万一你不小心最小化了：工具会弹一次提示，还原窗口再用「挪走」即可。

**其他状态**：被别的窗口盖住、切到别的程序、换虚拟桌面 —— 这些都不影响保活
（只要窗口没被最小化）。

想全停：**托盘菜单 →「取消所有保活」**。

> ⚠️ 两句实话：
> 1. 云原神的"无操作自动退出"有一部分就是为了**别白白烧你的付费时长**。
>    开着保活挂机，时长照样在走 —— 这是你的选择，但心里有数。
> 2. 云游戏服务通常不欢迎自动化保活（占着云端算力）。自己用就行，别拿去做别的。

## 鼠标移出就隐藏

点面板上的**「隐藏」**开启。开启后：

- 鼠标离开这个窗口的范围 → 窗口被压到**完全透明**（透明度 0%，看不见）
- 鼠标移回窗口原来的位置 → 立刻恢复成你设定的透明度
- 窗口本身**还在原位、没被最小化**，只是看不见，所以移回去就能认出来

按程序记住（和透明度一样），下次这个程序再开窗口会自动生效。

> 万一找不回来：**托盘菜单 →「取消所有自动隐藏」**，或者双击托盘图标暂停、
> 直接退出程序都行（退出时会自动把所有窗口恢复原样）。
>
> 注意：这是"看不见"而不是"最小化"。窗口如果被别的窗口完全盖住，
> 鼠标移不到它的范围里，就恢复不了 —— 这种情况用托盘菜单那个逃生口。

## 连按按键（挂机用）

场景：游戏里按 `F` 选对话，你想让它自己一直按下去。

1. 鼠标移到游戏窗口标题栏 → 点开面板 → **左键点「连按」**。
2. 第一次会弹出设置窗：点「点这里，然后按下要连按的键」，按一下 `F`，设好间隔，确定。
3. 它就开始自己按了。**小胶囊会变成绿色**，一眼能看出正在跑。
4. 想停：再点一次「连按」，或按 `Ctrl+Alt+K`，或 `Ctrl+Alt+P` 一键全停。

**右键点「连按」**可以随时改键、改间隔、换发送方式。

### 快捷键（不动鼠标就能操作）

**托盘菜单 →「快捷键设置…」**（菜单项上会直接显示当前已启用的快捷键）。
在「连按按键设置」对话框里也有一个「快捷键设置…」按钮可以直接跳过去。

| 动作 | 出厂设置 | 说明 |
| --- | --- | --- |
| 连按开关 | 连按 2 次鼠标侧键2 | 默认关 |
| 最小化窗口 | 按一下鼠标中键 | 默认关 |
| 窗口置顶 | 按一下 F2 | 默认关 |
| 鼠标穿透 | 长按 F3 | 默认关 |
| **挪回窗口** | **Ctrl+Alt+B** | **默认开** —— 这是逃生快捷键，别关 |

对话框里四个动作各一个标签页：

| 动作 | 说明 |
| --- | --- |
| 连按开关 | 开 / 关连按，作用于最近一次开过连按的窗口 |
| **最小化窗口** | 按一次最小化当前窗口，**再按一次把它还原回来**（切换） |
| 窗口置顶 | 对当前前台窗口切换「总在最前」 |
| 鼠标穿透 | 对当前前台窗口切换鼠标穿透 |

每一项都能单独配：

- **触发键**：鼠标侧键1（后退）、侧键2（前进）、中键，或者任意键盘按键（含 `Ctrl+` 组合）。
- **怎么算「按下了」**（防误触）：
  - **按一下就触发** —— 不防误触，适合最小化这种希望干脆利落的。
  - **连按 N 次** —— 默认 2 次，且相邻两次间隔不超过 0.7 秒。走路时蹭到一下不算数。
  - **长按 N 秒** —— 默认 0.8 秒。按住不放才触发。
- **是否拦截这个键**：默认**不拦截**，该键原本的功能照常（比如侧键1在浏览器里还是"后退"）。
  勾上之后它就变成专用开关，系统里任何程序都收不到它了。

> 用的是全局低级键鼠钩子（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`），
> 所以鼠标侧键、裸键这种 `RegisterHotKey` 抓不到的组合也能用。
> 只装需要的那一个钩子；钩子回调里只做几个整数比较，重活交给定时器 ——
> 拖慢系统输入是会被 Windows 直接摘掉钩子的。

### 设置项

- **按键**：任意单键，也支持 `Ctrl+F` 这种组合键。
- **间隔**：0.05 ~ 10 秒之间选一个区间，**每次在这个区间里随机取**，比固定节奏自然。
- **发送方式**（三档）：
  - **`前台用真实按键，后台投递给窗口`（默认，推荐）** —— 窗口在前台时用 `SendInput` 发真实按键
    （游戏基本都吃这套）；窗口切到后台自动改用 `PostMessage` 直接投给窗口，
    **所以你切去干别的事，它照样继续按**。
  - `仅当该窗口在前台时发送`（最保守）—— 窗口一旦切到后台就暂停，绝不往别处发。
  - `始终后台投递给窗口` —— 一律用 `PostMessage`。只对一部分程序有效。
- **保存后立即开始连按**：取消勾选就只保存配置不启动。

> 后台投递会优先投给该窗口线程里真正持有键盘焦点的子窗口（很多游戏是这样收键的），
> 拿不到才退回顶层窗口，命中率比直接投顶层窗口高不少。

### 安全设计

这功能本质上是"替你敲键盘"，所以做了几层保险：

- **两种发送方式都不会污染别的窗口**：`SendInput` 只在目标窗口处于前台时使用；
  `PostMessage` 是点对点投递给指定窗口的，本来就打不到别处。
- 打开设置对话框前会**先停掉连按**，免得按键打进对话框。
- 停止时一定会补一次"抬键"，不会让游戏以为键一直按着。
- 目标窗口被关闭 / 最小化时自动停。
- 退出程序时自动停掉所有连按。
- `Ctrl+Alt+P` 一键停止所有连按，`Ctrl+Alt+H`（暂停悬停按钮）也会顺带全停。
- 配置按进程名记住，但**不会自动启动** —— 每次都要你手动开，避免"打开某个程序突然被狂按键盘"。

## 托盘菜单

- **启用悬停按钮** —— 总开关
- **触发区域** —— `只在标题栏`（默认，推荐）/ `整个窗口`
- **记住每个程序的透明度** —— 按进程名记录，下次打开同一程序可以自动套用
- **新窗口自动套用记住的透明度** —— 默认关闭，开了之后新窗口会按记录自动变透明
- **启用全局热键**
- **渲染方式** —— `分层窗口`（默认，通用）/ `亚克力混合`
- **调整当前窗口** —— 直接对前台窗口设 100%~20%
- **恢复所有窗口** —— 把接管过的窗口全部还原
- **取消所有鼠标穿透** —— 一键解除所有窗口的鼠标穿透（脱困用，见下）
- **连按按键设置（当前窗口）…** —— 给前台窗口配置连按
- **停止所有连按** —— 一键停掉所有窗口的连按
- **快捷键设置…** —— 配全局快捷键（连按开关 / 最小化 / 置顶 / 穿透），菜单上会显示当前设置
- **取消所有自动隐藏** —— 把被「鼠标移出就隐藏」藏起来的窗口全部恢复出来
- **取消所有保活** —— 一次关掉所有窗口的保活
- **开机自动启动** —— 写 `HKCU\...\Run`，不需要管理员
- **退出** —— 退出前会把所有窗口恢复原样

## 关于「鼠标穿透」

穿透开启后，鼠标点不到那个窗口了 —— 这正是它的用途。但它也带来一个陷阱：
窗口收不到鼠标消息，`WindowFromPoint` 只会返回它背后的窗口，工具就再也"认不出"它了。

本工具对此做了两层兜底：

1. **仍然能悬停到它**。鼠标移到穿透窗口的标题栏上，按钮照常出现、面板照常展开，
   点「穿透」就能关掉。（实现上是沿着 z 序往上找我们自己标记过的穿透窗口，
   而不是依赖系统的命中测试。）
2. **托盘菜单 →「取消所有鼠标穿透」**。万一那个窗口被别的窗口整个盖住、
   连标题栏都露不出来，用这个一键解除，不用退出软件。

## 实现说明

- **透明度方案**：给目标窗口挂上 `WS_EX_LAYERED`，再用 `SetLayeredWindowAttributes(LWA_ALPHA)`。
  这是最通用的做法，整个窗口（标题栏 + 内容）一起变透明，且不需要目标进程配合。
  如果窗口本来就是分层窗口，则改用 `SetWindowCompositionAttribute` 的亚克力方案，避免破坏它自己的用法。
- **悬停按钮**：一个全自绘的无边框窗体，带 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，
  所以它不抢焦点、不进 Alt+Tab。主循环用 55ms 定时器 + `WindowFromPoint` 找鼠标下的窗口，
  坐标按目标窗口 DPI 缩放（PerMonitorV2）。
- **定位**：按钮放在标题栏右侧，并按 `GetSystemMetricsForDpi(SM_CXSIZE)` 预留出
  最小化 / 最大化 / 关闭三个按钮的位置，不会挡住关闭键。窗口太窄时自动居中。
- **穿透窗口的再识别**：`FindClickThroughUnderCursor` 从鼠标下的窗口沿 `GW_HWNDPREV`
  往上走 z 序，找出我们自己设过穿透、且鼠标落在其触发区域内的窗口。没有这一步，
  用户一开穿透就再也点不回来，只能退出软件。
- **连按的发送通道**：`SendInput`（真实按键，需要目标在前台）和 `PostMessage`（点对点投递，
  后台可用）两条路。默认 Hybrid 模式：前台走前者、后台走后者。
  `PostMessage` 前会用 `GetGUIThreadInfo` 找到目标线程里真正持有键盘焦点的子窗口，
  命中率比投顶层窗口高。抬键时用和按下时同一条通道，避免键卡在按下状态。
- **触发键**：`WH_KEYBOARD_LL` / `WH_MOUSE_LL` 全局钩子，可以同时管多个绑定。
  只装需要的那一个（全是鼠标键就不装键盘钩子），减少对系统输入的影响。
  修饰键状态由钩子自己维护，因为在回调里 `GetAsyncKeyState` 拿到的可能还是上一刻的值。
- **按键注入不能在钩子线程上做**（这条踩过大坑）：注入的事件要经过钩子回调，
  而回调是在装钩子的那个线程上跑的。如果那个线程正卡在 `SendInput` 里等注入完成，
  回调就没机会执行，超时（默认 300ms）后 Windows 会把钩子**直接摘掉** ——
  症状是"连按一开，全局快捷键全失灵"。所以按键注入走独立的发送线程。
- **只忽略自己注入的键**：注入时在 `dwExtraInfo` 里放一个标记，钩子看到标记就跳过。
  不能一刀切过滤所有 `injected` 事件 —— 很多游戏鼠标用软件改侧键，
  那些事件同样带 injected 标记，过滤掉的话快捷键就失灵了。
- **钩子回调必须极快**：鼠标移动事件占了绝大多数，先按消息号过滤掉，
  再用 `Marshal.ReadInt32` 按偏移直接读字段，不做 `PtrToStructure` 结构体解析。
- **最小化是「切换」而不是单向**：记住最近一次被快捷键最小化的窗口，
  再按一次还原它。否则最小化之后前台窗口就变了，没法还原。
- **「鼠标移出就隐藏」用窗口矩形判定，不走 `WindowFromPoint`**：
  窗口被压成 alpha=0 之后取点判断不稳，而且「移出窗口」按字面就是看矩形范围。
  隐藏用的是 `SetLayeredWindowAttributes(alpha=0)`，**不能走 `Fx.Apply()`** ——
  那条路有 `MinPercent = 10` 的下限（防止用户把窗口调没了找不回来），
  而自动隐藏是用户明确要的「看不见」，所以单独一条 `SetHiddenAlpha`。
  `WinState.Hidden` 必须和窗口实际 alpha 保持一致，别只改标志位不真去改窗口。
- **保活用 `PostMessage` 而不是 `SendInput`**：`SendInput` 只能发到前台窗口，
  窗口在后台时会打到用户正在用的程序上。`PostMessage` 能定向发给指定窗口，
  而且实测浏览器会把它当**真实输入**（页面里 `isTrusted = true`），
  云游戏客户端会正常转发。
- **保活默认发按键，不发鼠标**：实测 `PostMessage` 注入的 `mousemove`，
  页面里 `movementX/movementY` **恒为 0**（浏览器从真实输入设备的位移算，
  合成的窗口消息没这个信息）。而第三人称游戏用「指针锁定 + 相对位移」控视角，
  客户端发的就是 movementX/Y —— 全 0 等于没输入。`keydown` 没有这个概念，一定会被转发。
  （对照组：真实鼠标移动时页面里 `movementX` 是 -224 这种量级。）
- **W/S 要成对发**：只按 W 角色会一直往前走，每分钟一次就会慢慢飘走；
  点一下 W 再点一下等长的 S，走一小步再退回来，净位移约 0。
- **最小化的窗口收不到注入的输入**（实测 `PostMessage` / `SendMessage` / 发子窗口全无效，
  还原后立刻恢复）—— 浏览器在最小化时直接丢弃这些消息。
  所以「保活」的搭档是 `Fx.MoveAway`：**把窗口挪到屏幕外**（不最小化），
  那样看不见但注入照常生效。
- **退出即还原**：所有被接管的窗口都记录了原始样式，退出 / 重置 / 恢复所有窗口时逐一还原。

## 已知限制

- 以**管理员权限**运行的程序（任务管理器、部分游戏反作弊窗口等），本工具也需要以管理员身份启动才能控制。
- UWP / 系统级窗口（开始菜单、任务栏、桌面）会被自动跳过。
- 少数使用硬件加速 DirectComposition 的窗口对分层样式不友好，如出现异常可在托盘里切到「亚克力混合」。
- 如果同时开着 WindowTop 之类的同类工具，两者可能对同一窗口互相覆盖样式，建议只留一个。
- **连按对只认"原始键盘输入"（Raw Input / DirectInput）的程序无效**。这类程序直接读硬件键盘状态，
  收不到 `PostMessage`，后台模式下会没反应；只有窗口在前台走 `SendInput` 时才有效。
  这是 Windows 的机制限制，除非上驱动级方案。

## 关于游戏里用

这个工具本质是"软件宏"。**用之前先看清楚游戏厂商的规则**：

- 很多在线游戏的用户协议明确禁止"模拟用户操作的第三方工具"，包括只是连点某个键。
  米哈游 2025 年 11 月专门发过公告打击鼠标宏/自动化脚本，明确点名"自动跳过剧情"这类
  看似无害的用法同样在打击范围内，处罚包括封号。
- **优先用游戏自带的官方功能**。比如《原神》设置里有「自动播放剧情」，就是你想要的效果，
  零风险。
- 云游戏（比如网页版云·原神）里本工具只是在对浏览器发按键，检测面不一样，但严格说同样
  属于"改变操作环境"。
- 决策权在你，风险也在你。真要用，建议把间隔设大一点（1 秒以上）、别在涉及排名或
  奖励获取的场景用。

## 排查

- 日志：`%APPDATA%\AmoWinTrans\AmoWinTrans.log`
- **快捷键按了没反应？** 日志里搜 `EVENT` —— 每次快捷键触发、连按开关都会记一行，
  不需要开 `--verbose`。如果按了键但日志里没有对应记录，说明钩子没收到按键。
- 想看详细流程：`AmoWinTrans.exe --verbose`（或设环境变量 `AMOWINTRANS_VERBOSE=1`）
- 配置：`%APPDATA%\AmoWinTrans\settings.ini`

## 相关脚本

### `浏览器脚本-离开网页自动黑白.user.js`

**按标签页手动开关**：默认所有页面都不生效，在想要的那个页面按 **`Alt+G`** 开启，
之后鼠标移出网页（或切走窗口 / 标签页）自动变黑白，移回恢复。再按一次关掉。

- 状态**跟着标签页走**，在同一个标签里跨站跳转也不会丢
  （用 `window.name` 记的 —— `sessionStorage` 是按网站隔离的，跳个站就没了）
- 开关时会弹一个提示，告诉你当前状态
- 脚本顶部有两个可改的配置：
  - `HOTKEY` —— 换快捷键
  - `ENABLED_BY_DEFAULT` —— 改成 `true` 就是所有标签页默认开启（回到"全局生效"）

**为什么没做进工具里**：Windows 没有"单个窗口变灰度"的现成 API。
唯一的路子是放大镜 API 的窗口版控件（`WC_MAGNIFIER`），但**这个控件在 Windows 10/11 上已经失效**——
实测 `MagSetWindowTransform` / `MagSetWindowSource` / `MagSetColorEffect` 全部返回 FALSE
（两个候选类名 × 两种调用顺序，四种组合都失败），而同一个 DLL 的
`MagSetFullscreenColorEffect` 却正常工作，说明是窗口版控件被微软废弃了，不是调用姿势的问题。

所以浏览器场景改用 CSS 滤镜：**更简单、无延迟、不受窗口遮挡影响**。

安装：

1. 装个 [Tampermonkey](https://www.tampermonkey.net/) 或 Violentmonkey 扩展（这一步才是在扩展商店里装）
2. 把 `.user.js` 拖进浏览器窗口 → Tampermonkey 弹出安装页 → 点「安装」
3. **打开「允许用户脚本」开关**（关键，不打开脚本不会执行）：
   地址栏输入 `edge://extensions`（Chrome 是 `chrome://extensions`）→
   Tampermonkey → **「详细信息」** → 打开 **「允许用户脚本」**
   > Chrome / Edge **138 版之后**新增的限制：用户脚本默认不执行，
   > 必须在扩展设置里手动开这个开关（或开「开发人员模式」）。
   > 开着「开发人员模式」会让浏览器每次启动弹提示，所以推荐用前者。
4. 回到网页**按 F5 刷新**（脚本只在页面加载时注入）

排查：如果装了没反应，先看 Tampermonkey 图标上的数字角标
（有数字 = 当前页有脚本在跑）。数字是 0 或没有角标，就是第 3 步的开关没开。

> 小提示：`filter` 加在 `<html>` 上会让少数网站的 `position: fixed` 元素跟着滚动。
> 遇到这种网站按 `Alt+G` 关掉就行。

## 自己编译

需要 .NET SDK 8 或更高（本机已装 10.0.301）。

```bat
build.bat             :: 编译到 bin\Release\net8.0-windows\AmoWinTrans.exe
publish.bat           :: 发布"框架依赖"单文件到 dist\AmoWinTrans.exe（约 220 KB）
publish-portable.bat  :: 发布"零依赖"单文件到 dist-standalone\AmoWinTrans.exe（约 66 MB）
```

**要拷到别的电脑用，用 `publish-portable.bat` 那份。**

| | `dist\AmoWinTrans.exe` | `dist-standalone\AmoWinTrans.exe` |
| --- | --- | --- |
| 体积 | ~220 KB | ~66 MB |
| 目标机器要求 | 需要装 **.NET 8 Desktop Runtime** | **什么都不用装** |
| 适用 | 本机自用 | 拷到别的电脑 / 给别人 |

自包含版是把 .NET 运行时一起打进去了（用 `EnableCompressionInSingleFile` 压过），
首次启动会慢一两秒（要解压），之后就正常了。两个版本功能完全一样，
配置也都存在 `%APPDATA%\AmoWinTrans\`，所以换版本不用重新配。
